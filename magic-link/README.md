# magic-link: доступ к приложению по рабочей почте или ссылке-приглашению

Защита микро-приложения в один файл без зависимостей для каждого языка. Два способа пустить человека, их можно
сочетать:
- **по рабочей почте** — как доступ к Google Doc: владелец перечисляет адреса, человек вводит свою почту и входит
  по ссылке из письма;
- **по ссылке-приглашению** с токеном — общим или личным на каждого человека.

| Файл | Для чего |
|---|---|
| [magic_link.py](magic_link.py) | `MagicLink` — WSGI (Flask, Django, Bottle, `wsgiref`); `MagicLinkASGI` — ASGI (FastAPI, Starlette); Python 3.8+ |
| [magic-link.js](magic-link.js) | middleware `(req, res, next)`: Express, Connect, чистый `http`; Node 18+ |

Скопируйте нужный файл в папку приложения. `small deploy` загружает только эту папку. Проще всего начать с
`small init`: он кладёт эти файлы в новую заготовку сам. Их копии лежат в `small-cli/small_cli/templates/`. После
правки файлов здесь скопируйте их туда: тест `small-cli` упадёт, если копии разойдутся.

## Вход по рабочей почте

1. Владелец добавляет адреса в `ACCESS_EMAILS`: `ivan@company.com, @company.com` (`@домен` — все адреса домена).
   С `small`: `small access add ivan@company.com`.
2. Человек открывает приложение и видит «Вход по рабочей почте». Вводит адрес и получает письмо со ссылкой.
3. Ссылка действует **15 минут и только один раз**. Открыв её, человек нажимает «Войти»: вход по кнопке, а не по
   самому открытию, потому что корпоративные почтовые сканеры открывают ссылки из писем сами и иначе «съедали» бы
   их. После входа кука `small_access` (HttpOnly, SameSite=Lax, Secure за HTTPS) держит вход 30 дней.
4. В лог пишется `[magic-link] вход по почте (ivan@company.com), ip=…`.

Что сделано для безопасности:
- **Пересылать нечего.** Войти может только тот, кто читает почту из списка.
- **Список не раскрывается.** На любой адрес ответ одинаковый: «Проверьте почту». Незнакомый адрес становится
  запросом доступа: строка `[access-request]` в логе и сообщение в Telegram с готовой командой
  `small access add адрес`.
- **Отзыв сразу.** Убрали адрес из `ACCESS_EMAILS` — после перезапуска не пускает и уже выданная кука.
- **Подпись.** Ссылки и сессии подписаны HMAC-SHA256 ключом `SESSION_SECRET`, с разным назначением: ссылку
  для входа нельзя выдать за сессию, и наоборот.
- **Адрес в письме не подменить.** Ссылка строится из `PUBLIC_URL` или `RAILWAY_PUBLIC_DOMAIN`, а не из заголовка
  `Host` (ему верим только для localhost). Иначе злоумышленник подставил бы свой домен, и ссылка для входа из
  настоящего письма ушла бы к нему.
- **Лимит.** Не больше 3 писем на адрес и 10 запросов с одного IP за 15 минут.

Отправка писем:
- **Resend** (`RESEND_API_KEY`, `MAIL_FROM`) — по HTTPS, работает и на Railway Hobby, где SMTP-порты закрыты
  ([документация Railway](https://docs.railway.com/networking/outbound-networking)). Без подтверждённого домена
  Resend шлёт только на адрес владельца аккаунта.
- **SMTP** (`SMTP_URL=smtp://логин:пароль@сервер:587` или `smtps://…:465`) — свой почтовый сервер. На Railway — с
  тарифа Pro. Только в Python-версии.
- **`LOGIN_LINKS_TO_LOG=1`** — вместо письма ссылка пишется в лог. Только для проверки.

С `small` всё это настраивает `small mail resend` (или `smtp`, `log`): он отправляет пробное письмо и только потом
сохраняет настройки.

## Ссылка-приглашение

1. Владелец раздаёт ссылку `https://<app>.up.railway.app/?token=<токен>`.
2. По ней middleware ставит куку `small_access` (30 дней) и делает редирект на тот же адрес **без** `token`, чтобы
   токен не оставался в истории браузера. В лог пишется `[magic-link] вход по ссылке (имя), ip=…`; токена в ней нет.
3. Без доступа отдаётся **403**: форма входа по почте, если задан `ACCESS_EMAILS`, иначе кнопка «Запросить доступ».
   Кнопка ведёт на `ACCESS_REQUEST_URL` (`mailto:`, Telegram, Google Form) или открывает форму «Email или Telegram
   для ответа»; запрос печатается в лог строкой `[access-request] ...` и, если заданы `TELEGRAM_BOT_TOKEN` и
   `TELEGRAM_CHAT_ID`, приходит в Telegram. Отправка в фоне, без разметки текста; если Telegram недоступен,
   пользователь всё равно видит «Запрос отправлен».

В куке хранится не сам токен, а производное от него. Если убрать из `ACCESS_TOKEN` токен одного человека (после
перезапуска), перестанут работать его ссылка и его кука; у остальных всё останется как было.

```
small access add bob       # выдать bob личную ссылку
small access revoke bob    # отозвать
```

Вручную: имя — до двоеточия, в самом токене двоеточия быть не должно. Сгенерировать токен:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

## Переменные

| Переменная | Значение |
|---|---|
| `ACCESS_EMAILS` | адреса через запятую; `@company.com` — весь домен |
| `SESSION_SECRET` | ключ подписи ссылок для входа и сессий. Не задан — случайный на каждый запуск: после перезапуска все входят заново. `small access add адрес` создаёт его сам |
| `RESEND_API_KEY`, `MAIL_FROM` | письма через Resend; `MAIL_FROM` — «Отчёты &lt;noreply@company.com&gt;» |
| `SMTP_URL` | письма через SMTP (только Python) |
| `LOGIN_LINKS_TO_LOG` | `1` — ссылка для входа в лог вместо письма (проверка) |
| `PUBLIC_URL` | адрес приложения для ссылок в письмах, например свой домен; по умолчанию `https://$RAILWAY_PUBLIC_DOMAIN`. После переименования домена Railway оставляет там прежний адрес, поэтому `small deploy` и `small access add` задают `PUBLIC_URL` сами |
| `ACCESS_LANG` | язык страниц и писем: `ru`, `en` или `auto` (по умолчанию — по языку браузера: русским по-русски, остальным по-английски) |
| `ACCESS_TOKEN` | токены ссылок-приглашений через запятую; можно с именами: `alice:токен1,bob:токен2` |
| `ACCESS_REQUEST_URL` | куда ведёт кнопка «Запросить доступ», если нет входа по почте |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | запросы доступа приходят владельцу в Telegram (`small notify telegram`) |

Ни `ACCESS_EMAILS`, ни `ACCESS_TOKEN` не заданы — доступ закрыт для всех.
`/_access/logout` — выйти (кука удаляется).

## Подключение

**Python, WSGI**

```python
from magic_link import MagicLink

application = MagicLink(application)        # любой WSGI
app.wsgi_app = MagicLink(app.wsgi_app)      # Flask
```

Для Django: в `wsgi.py` `application = MagicLink(get_wsgi_application())`.
Пример: шаблон [python-http/app.py](../small-cli/small_cli/templates/python-http/app.py).

**Python, ASGI**

```python
from magic_link import MagicLinkASGI

app.add_middleware(MagicLinkASGI)           # FastAPI / Starlette
app = MagicLinkASGI(app)                    # любой ASGI
```

Закрыты все HTTP-запросы, в том числе `/docs`. Websocket без куки закрывается до установки соединения, сервер
отвечает 403. Lifespan проходит без проверки. Пример: шаблон
[fastapi/main.py](../small-cli/small_cli/templates/fastapi/main.py); в нём же фильтр, который прячет `?token=`
из access-лога `uvicorn`.

У обеих версий параметры конструктора `tokens=`, `emails=`, `secret=`, `request_url=`, `cookie_name=` и
`max_age=` переопределяют переменные окружения.

**Node.js**

```js
const magicLink = require('./magic-link');

app.use(magicLink());                                   // Express: всё приложение
app.use('/admin', magicLink());                         // или только раздел

const guard = magicLink();                              // чистый http
http.createServer((req, res) => guard(req, res, () => handler(req, res)));
```

Опции: `{ tokens, emails, secret, requestUrl, cookieName, maxAge }`. Письма — только через Resend: SMTP в Node
без зависимостей не отправить.

## Чего эта защита не делает

- **Нет паролей и ролей.** Вход по почте подтверждает владение адресом; у всех вошедших одинаковые права.
- **Ссылка-приглашение — это пароль в адресе.** Кто её получил, тот и войдёт; для коллег лучше вход по почте.
  Первый запрос `/?token=...` попадает в access-логи сервера и прокси Railway. В шаблонах `python-http` и `fastapi`
  токен в логах сервера маскируется (`token=***`). В своём сервере (gunicorn, morgan) сделайте так же.
- **Одноразовость ссылок и лимиты — в памяти процесса.** Для микро-приложения с одним экземпляром этого достаточно;
  при нескольких экземплярах ссылку можно использовать по разу в каждом.
- **Отзыв срабатывает после перезапуска:** списки читаются при старте. `small access revoke` перезапускает сам.
- Для чувствительных данных нужна полноценная авторизация с ролями и аудитом.

## Тесты

```bash
python -m unittest test_magic_link     # 50: WSGI, ASGI, вход по почте, языки, личные токены, Telegram, Resend, SMTP
node --test                            # 19
```

Проверяются:
- 403 с формой входа или кнопкой «Запросить доступ»;
- редирект без токена и флаги куки, Secure за прокси, открытый редирект;
- неверный токен, поддельная кука, личные токены и их отзыв;
- вход по почте: письмо, кнопка «Войти» (сканер не тратит ссылку), одноразовость, срок 15 минут;
- одинаковый ответ на известный и незнакомый адрес, запрос доступа, домен целиком;
- отзыв адреса закрывает уже выданную сессию; подделка сессии и чужой ключ не проходят;
- лимит писем, неверный адрес, заголовок `Host` не подменяет ссылку, `PUBLIC_URL`, выход;
- отправка через Resend и SMTP, ошибки без ключей и паролей в логе, режим лога;
- журнал запросов доступа без инъекции строк, Telegram и его недоступность;
- для ASGI ещё websocket и lifespan.
