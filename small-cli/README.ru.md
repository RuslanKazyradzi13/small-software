# small: деплой в Railway одной командой

[English version](https://github.com/RuslanKazyradzi13/small-software/blob/main/small-cli/README.md)

```
small init my-service    # заготовка: сервер с защитой по ссылке, small.json, .gitignore
cd my-service
small deploy             # → https://my-service-3f9a.up.railway.app
small open               # открыть по ссылке-приглашению
small access add ivan@company.com   # кто может войти — как доступ к Google Doc
small sso google         # «Войти через Google» (или small sso microsoft)
small mail resend        # или ссылки для входа на почту
small access log         # кто, когда и как входил
small access add bob     # или личная ссылка для bob (small access revoke bob — отозвать)
small notify telegram    # запросы доступа — в Telegram
small env set DEBUG=1    # переменная окружения в Railway и small.json
small db add postgres    # база данных, DATABASE_URL — в приложении
small volume add         # постоянный диск: файлы и состояние входа переживают деплои
small domain add app.example.com   # свой домен
small sleep on           # засыпать без запросов (экономия)
small logs -f            # логи приложения
small dashboard          # все приложения в браузере: статус, расход, логи
small destroy            # удалить из Railway вместе с базами
```

Можно деплоить и уже готовую папку с кодом (`app.py`, `main.py`, `package.json` и т.п.): `small init` не обязателен.

Python 3.9+, без внешних зависимостей.

## Установка

```bash
pip install small-software
```

Пакет ставится с PyPI, команда — `small`. Через [pipx](https://pipx.pypa.io): `pipx install small-software`.

Из исходников, в клоне репозитория:

```bash
pip install ./small-cli
```

**Windows (рекомендуется): одна команда в PowerShell.**

```powershell
irm https://raw.githubusercontent.com/RuslanKazyradzi13/small-software/main/install.ps1 | iex
```

Установщик ставит small в отдельное окружение Python в `%LOCALAPPDATA%\Programs\small` и добавляет команду
`small`, которую не блокирует Smart App Control (неподписанного `small.exe` нет). Нужен Python 3.9+, права
администратора не нужны; повторный запуск обновляет small. Удаление:

```powershell
& ([scriptblock]::Create((irm https://raw.githubusercontent.com/RuslanKazyradzi13/small-software/main/install.ps1))) -Uninstall
```

Значения с `&` или `|` (например, URL) передавайте через стоп-токен PowerShell:
`small --% env set "URL=https://x?a=1&b=2"`.

**Windows через pip.** `pip install` создаёт `small.exe`. Он не подписан, и Smart App Control / Application
Control в Windows может его заблокировать. Тогда есть два пути:

- запускать через Python, это работает везде: `python -m small_cli deploy` (так запускается любая команда);
- или добавить папку `small-cli` из клона репозитория в `PATH`, и команду `small` будет обслуживать `small.cmd`.
  Выполните в корне клона (`$PWD` подставит его путь), затем откройте новый терминал:

```powershell
[Environment]::SetEnvironmentVariable("Path", $env:Path + ";$PWD\small-cli", "User")
```

## Язык

small говорит по-английски и по-русски. Русский выбирается, если язык системы русский (`LC_ALL`, `LC_MESSAGES`,
`LANG`, `LANGUAGE` или язык интерфейса Windows), иначе английский. Задать язык явно: `SMALL_LANG=en` или
`SMALL_LANG=ru`.

```bash
export SMALL_LANG=en
```

```powershell
$env:SMALL_LANG = "en"
```

У задеплоенных приложений язык свой:

- **Страницы входа и письма** — на языке браузера каждого посетителя. `ACCESS_LANG=ru` или `ACCESS_LANG=en`
  задаёт один язык для всех.
- **Строки лога и уведомления в Telegram** пишутся для владельца, на языке `OWNER_LANG=en|ru`. `small deploy`
  ставит `OWNER_LANG` по языку small, если он не задан в `small.json`. Это происходит, только если в `env` из
  `small.json` есть хотя бы одна переменная (у приложений из `small init` она есть всегда): приложению с пустым
  `env` `small deploy` не передаёт никаких переменных.

## Токен

Нужен **токен аккаунта** или **токен workspace** (Railway → Account Settings → Tokens). Токен проекта не подойдёт:
он не умеет создавать проекты.

Сохраните токен в переменную `RAILWAY_API_TOKEN`, заменив `ВАШ_ТОКЕН` целиком. Внутри кавычек должен остаться только
токен вида `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`:

```powershell
[Environment]::SetEnvironmentVariable("RAILWAY_API_TOKEN", "ВАШ_ТОКЕН", "User")  # навсегда
$env:RAILWAY_API_TOKEN = "ВАШ_ТОКЕН"                                          # только этот терминал
```

Переменная, сохранённая «навсегда», видна новым окнам терминала. Уже открытые окна и приложения её не видят, их
нужно перезапустить. Пробелы, кавычки и угловые скобки по краям токена `small` отбрасывает сам.

Резервное имя переменной: `RAILWAY_TOKEN`.

## `small init`: заготовка приложения

```
small init [папка] [--template python-http|node-http|fastapi|streamlit] [--name NAME] [--force]
```

Создаёт в папке (по умолчанию текущей; если её нет, она создаётся) готовое к деплою микро-приложение.
Шаблон выбирается флагом `--template` (коротко `-t`), по умолчанию `python-http`:

| Файл | Что это |
|---|---|
| `app.py` + `magic_link.py` (`python-http`, по умолчанию) | веб-сервер на стандартной библиотеке (`wsgiref`); весь код в `app()` |
| `server.js` + `magic-link.js` + `package.json` (`node-http`) | веб-сервер на модуле `http`, Node 18+; весь код в `handler()` |
| `main.py` + `magic_link.py` + `requirements.txt` (`fastapi`) | API на FastAPI + uvicorn: страница, `/api/hello`, документация `/docs`; защита — `MagicLinkASGI`, в логах uvicorn токен скрыт. Railway сам запускает `uvicorn main:app` |
| `app.py` + `requirements.txt` (`streamlit`) | интерактивное приложение на [Streamlit](https://streamlit.io): боковая панель с параметрами, метрики, график, таблица с выгрузкой CSV; вход по ссылке встроен в `app.py` |
| `small.json` | уникальное имя проекта и сгенерированный `ACCESS_TOKEN` в `env` |
| `.gitignore` | `small.json`, `.small.json`, `.env` и мусор языка (`__pycache__/`, `node_modules/`…) |
| `.railwayignore` | то, что нужно в git, но не нужно в Railway: `*.md`, `tests/`, настройки IDE |

Приложения-примеры — на английском: и текст страницы, и комментарии в коде.

- **Защита по ссылке-приглашению.** Шаблоны включают защиту сразу, на основе
  [magic-link](https://github.com/RuslanKazyradzi13/small-software/blob/main/magic-link/README.md).
  `small deploy` передаёт `ACCESS_TOKEN` из `small.json` в Railway. Приложение открывается по ссылке
  `https://<домен>/?token=<ACCESS_TOKEN>`, без неё показывается страница 403 с кнопкой «Запросить доступ».
  Сервер слушает `$HOST:$PORT`, по умолчанию `0.0.0.0` и `PORT` от Railway.
- **Шаблон `streamlit`.** Streamlit нельзя обернуть middleware, поэтому `require_access()` в `app.py` опирается на
  `MagicLinkGate` из `magic_link.py`: те же переменные (`ACCESS_EMAILS`, `ACCESS_TOKEN`, `SESSION_SECRET`,
  `ACCESS_REQUEST_URL`...), одноразовые ссылки, лимиты и журнал, что и в других шаблонах, а экран доступа — на языке
  браузера посетителя. Отличия:
  - Вход по почте: ссылка из письма ведёт на `https://<домен>/?t=...` и показывает кнопку **Войти** — входит только
    нажатие. Сессию на 30 дней хранит подписанная кука, которую пишет крошечный фрейм того же origin, поэтому, в
    отличие от других шаблонов, она **не HttpOnly**: не выводите в защищённом приложении чужой HTML. **Выйти** — в
    боковой панели.
  - Личные ссылки оставляют токен в адресной строке (`?token=`) — так доступ переживает перезагрузку страницы.
  - Streamlit — одностраничное приложение, поэтому экран «нет доступа» отдаётся с HTTP-кодом 200, а не 403.
  Railway запускает `python app.py`; `app.py` при этом сам перезапускается через `streamlit run` на `$HOST:$PORT`.
  Локально можно запустить так же: `python app.py`.
- **Имя** по умолчанию: имя папки со случайным суффиксом, например `my-service-3f9a`. Явное имя в `small.json`
  привязывает деплой к одноимённому проекту в Railway, поэтому имя не должно случайно совпасть с чужим проектом.
  Суффикс к тому же повышает шанс, что поддомен `<name>.up.railway.app` свободен. `--name` задаёт имя без суффикса.
- **`small.json`** попадает в `.gitignore`, потому что в нём токен. Не публикуйте его.

**Существующие файлы не перезаписываются.** Если в папке уже есть файлы, которые создаёт шаблон:
- в терминале `small init` перечисляет их и спрашивает `Перезаписать? [y/N]`;
- без терминала (скрипт, CI) команда завершается с ошибкой. В обоих случаях при отказе в папке ничего не меняется.

`--force` перезаписывает без вопросов, в том числе `small.json`: появятся новое имя и новый `ACCESS_TOKEN`, а старые
ссылки-приглашения перестанут работать после следующего деплоя. `.gitignore` и `.railwayignore` никогда не
перезаписываются: в них дописываются только недостающие строки, повторный `init` ничего не дублирует.

## `small dashboard`: список приложений в браузере

```
small dashboard [папка] [--port N] [--no-browser]
```

Запускает локальный сервер и открывает браузер со списком всех микро-приложений в папке: по умолчанию в текущей,
можно указать любую, например `small dashboard ..`. Приложение — это папка с `small.json` и/или `.small.json`.

По каждому приложению показываются:
- имя: из `small.json`, иначе из `.small.json`, иначе имя папки;
- статус: **Привязан к Railway** (в `.small.json` есть ID сервиса) или **Не задеплоен**;
- **живой статус последнего деплоя** из Railway (`SUCCESS`, `BUILDING`, `FAILED`, `CRASHED`…), если задан токен;
- **«засыпает»** — включён режим сна (`small sleep on`);
- **оценка расхода** в $/мес при текущей нагрузке (см. ниже) и сумма по всем приложениям в строке-сводке;
- публичный URL и ссылка на сервис в консоли Railway, если приложение деплоилось;
- путь к папке;
- имена переменных из `small.json`, без значений;
- ошибки в `small.json` / `.small.json` — те же проверки, что у `small deploy`.

Кнопка **Обновить** пересканирует папки без перезапуска. Остановить сервер: `Ctrl+C`.

Кнопки в карточке задеплоенного приложения:
- **«Открыть по ссылке»** — открывает приложение сразу с токеном владельца, без экрана «Доступ по приглашению».
  Токен уходит только в адресную строку браузера при переходе, в данных страницы дашборда его нет.
- **«Логи»** — окно с последними 200 строками лога приложения или сборки (вкладки «Приложение» / «Сборка»).
  Нужен `RAILWAY_API_TOKEN`, без него кнопка неактивна.
- **«Поделиться»** показывает, у кого есть доступ: рабочие адреса, целые домены и имена личных ссылок (сами
  ссылки — никогда). Введите `ivan@company.com`, `@company.com` или имя и нажмите **Добавить**, либо
  **Отозвать** напротив нужной строки. Это то же, что `small access add` / `revoke`: меняются small.json и
  Railway, приложение перезапускается. Новая личная ссылка показывается один раз, с кнопкой «Копировать», и
  работает как пароль. Нужен `RAILWAY_API_TOKEN`. Страница и её запросы защищены: ключ на каждый запуск,
  проверка `Host`/`Origin`, запрет встраивания, только JSON.

- **Порт** по умолчанию 3000; если он занят, берётся любой свободный. URL печатается в stdout.
- **Сервер слушает только `127.0.0.1`** и отвечает 403 на запросы с чужим `Host` (защита от DNS rebinding).
  Значения переменных из `small.json` никогда не отдаются: в них лежит `ACCESS_TOKEN`.
- **Поиск** идёт до 6 уровней вглубь. Пропускаются `.git`, `node_modules`, `__pycache__`, `.venv`, `venv`, а внутрь
  найденного приложения сканер не спускается.
- Стили подключаются из Tailwind CDN; без интернета страница работает, но без оформления.

### Живые статусы деплоя

Если при запуске задан `RAILWAY_API_TOKEN` (или `RAILWAY_TOKEN`), при каждом обновлении дашборд спрашивает у Railway
последний деплой каждого привязанного приложения: запрос `serviceInstance(serviceId, environmentId) { latestDeployment }`.
Статус показывается цветным бейджем:

| Цвет | Статусы |
|---|---|
| зелёный | `SUCCESS` |
| голубой | `SLEEPING` |
| жёлтый с пульсом | `QUEUED`, `WAITING`, `INITIALIZING`, `BUILDING`, `DEPLOYING` |
| красный | `FAILED`, `CRASHED` |
| серый | остальные |

Подсказка на бейдже показывает время деплоя.

- **Без токена** дашборд работает в офлайн-режиме по локальным файлам и не обращается к Railway.
- **Ошибки** (нет сети, таймаут 5 с, неверный токен, удалённый сервис) не роняют сервер: такие карточки просто
  остаются без живого статуса, а в строке-сводке появляется пометка «Railway не ответил».
- **Скорость.** Запросы идут параллельно, поэтому даже медленный Railway задерживает обновление не больше чем на таймаут.
- **Безопасность.** Токен Railway остаётся в процессе дашборда и в браузер не отдаётся.

### Оценка расхода

Дашборд берёт у Railway замеры нагрузки проекта за последнюю неделю (запрос `metrics`: средние ядра CPU, ГБ памяти
и ГБ томов по часам, вместе с базами приложения) и умножает среднюю нагрузку на месячные тарифы из
[документации Railway](https://docs.railway.com/reference/pricing/plans): $20 за vCPU, $10 за ГБ памяти,
$0.15 за ГБ тома. Получается «≈ $X/мес при текущей нагрузке».
- **Сон и новые приложения.** Часы, когда приложение спало (`small sleep`), считаются нулём. Для нового
  приложения среднее берётся с его первого замера, поэтому оценка не занижается.
- **Почему не `usage`.** Накопленный расход из `usage` приходит с задержкой. На живой проверке он отличался от
  реальных замеров в 7–50 раз, причём по-разному для CPU и памяти, так что посчитать по нему честную сумму нельзя.
- **Это оценка, а не счёт.** Исходящий трафик ($0.05/ГБ), бесплатный лимит тарифа ($5 на Hobby, $20 на Pro) и
  подписка в неё не входят. Точная сумма — в Railway → Usage.

## `small mcp`: ИИ-агенты (Claude Code, Cursor...)

```
small mcp
```

Запускает [MCP](https://modelcontextprotocol.io)-сервер на stdin/stdout: ИИ-агент сам создаёт, деплоит и
расшаривает приложения — *«Задеплой эту папку и дай доступ ivan@company.com»*.

**Подключение:**
- **Claude Code:** `claude mcp add small -- small mcp` (Windows: `claude mcp add small -- cmd /c small mcp`).
- **Cursor** (`~/.cursor/mcp.json`), **Claude Desktop**, **Windsurf** и другие клиенты:

  ```json
  {"mcpServers": {"small": {"command": "small", "args": ["mcp"]}}}
  ```

  На Windows: `"command": "cmd", "args": ["/c", "small", "mcp"]` или `"command": "python", "args": ["-m",
  "small_cli", "mcp"]`, если small поставлен через pip.
- `RAILWAY_API_TOKEN` должен быть в окружении, из которого запускается агент. После того как задали — перезапустите
  агента.

**Инструменты:**

| Инструмент | Что делает |
|---|---|
| `init_app` | `small init`: готовое приложение из шаблона |
| `deploy_app` | `small deploy`: возвращает адрес; ход сборки приходит по мере работы |
| `share_app` | `small access add`: адрес, `@домен` или имя личной ссылки |
| `revoke_access` | `small access revoke` |
| `list_access` | `small access list` |
| `list_apps` | приложения в папке: адрес и статус последнего деплоя |
| `app_logs` | `small logs`: лог приложения или сборки |
| `set_env` | `small env set` / `unset` |

- **Удаления нет:** `small destroy` — только в терминале.
- **Лучше по почте.** Личная ссылка (имя вместо адреса) возвращается агенту и проходит через чат, как любой текст;
  при входе по почте секретов в чате нет.
- Инструменты выполняют тот же код, что и команды, и отвечают на языке small (`SMALL_LANG`). MCP-клиент обычно
  спрашивает разрешение перед каждым вызовом.

## `small deploy`

```
small deploy [папка] [--name NAME] [--workspace ID] [--port N] [-m MESSAGE] [--new] [--no-wait] [--timeout SEC]
```

| Флаг | Что делает |
|---|---|
| `--name` | имя проекта, сервиса и поддомена; главнее `name` из `small.json` (по умолчанию имя папки, приведённое к `a-z0-9-`) |
| `--workspace` | ID workspace, если у аккаунта их несколько (или `RAILWAY_WORKSPACE_ID`) |
| `--port` | порт для публичного домена, если приложение не слушает `$PORT` |
| `-m` | подпись деплоя в Railway |
| `--new` | создать новый проект, даже если папка уже деплоилась |
| `--no-wait` | вывести URL сразу, не дожидаясь сборки |
| `--timeout` | сколько секунд ждать сборку (по умолчанию 900) |

Прогресс пишется в stderr, итоговый URL в stdout: `URL=$(small deploy)`.
Коды выхода: `0` успех, `1` ошибка или упавшая сборка (последние строки лога выводятся), `130` прервано.

## После деплоя

Команды работают в папке задеплоенного приложения, то есть там, где есть `.small.json`. Для `link`, `open`, `logs`
и `destroy` путь передаётся аргументом, для остальных — через `-C папка`.

```
small link [папка] [--as ИМЯ]                       # напечатать ссылку-приглашение
small open [папка] [--as ИМЯ]                       # то же + открыть в браузере
small access [list | add ПОЧТА|@ДОМЕН|ИМЯ | revoke ПОЧТА|ИМЯ]   # кто может войти
small access log [-n N] [--json]                   # кто, когда и как входил
small access signout ПОЧТА|@ДОМЕН|--all            # завершить входы на всех устройствах
small sso [google [--client-id ID] | microsoft [--client-id ID] [--tenant T] | off [ПРОВАЙДЕР]]
small mail [resend | smtp [--from ОТ] [--to КОМУ] | log | off]  # письма для входа по почте
small notify [telegram [--chat-id ID] | off]        # запросы доступа в Telegram
small env [list [--values] | set K=V ... | unset K ...] [--no-deploy]
small db [list | add postgres | remove postgres [--yes]]
small volume [add [--mount /data]]                  # постоянный диск; без аргумента — статус
small domain [list | add ДОМЕН [--port N] | remove ДОМЕН]
small sleep [on | off]                              # режим сна; без аргумента — статус
small logs [папка] [--build] [-n N] [-f]            # лог последнего деплоя
small destroy [папка] [--yes]                       # удалить из Railway
```

Команды, которые меняют переменные приложения (`access add` / `revoke` / `signout`, `sso`, `mail`, `notify`,
`env set` / `unset`, `db add` / `remove`), `volume add` и `sleep on` / `off` один раз перезапускают приложение. С `--no-deploy` перезапуска не будет:
изменение вступит в силу при следующем деплое.

**`small link` / `small open`** собирают `https://<домен>/?token=<токен>`.
- **Откуда токен.** Из `small.json`, а если его там нет (например, токен задавали в дашборде Railway), то из переменных
  сервиса в Railway; для этого нужен `RAILWAY_API_TOKEN`. Без `--as` берётся первый токен (владельца),
  с `--as bob` — личный токен bob.
- **Если токена нигде нет**, печатается адрес без токена.
- **Вывод.** Ссылка уходит в stdout, так что её можно передать дальше: `small link | clip`. Она работает как пароль,
  поэтому пересылайте её только тем, кому нужен доступ.

**`small access`** — кто может открыть приложение. Два способа, их можно сочетать.

*По адресу* — как доступ к Google Doc, рекомендуемый способ:
- **`add ivan@company.com`** — адрес попадает в `ACCESS_EMAILS`. Иван открывает приложение и подтверждает, что адрес
  его: кнопкой **«Войти через Google / Microsoft»** (`small sso`) или ссылкой из письма (`small mail`), которая
  действует 15 минут и только один раз. Браузер помнит вход 30 дней. Пересланная ссылка ничего не даст: войдёт только
  владелец ящика или аккаунта.
- **`add @company.com`** — пускать всех с адресом в этом домене.
- **`revoke ivan@company.com`** — вход закрывается сразу после перезапуска, даже в уже открытом браузере. Время
  отзыва попадает и в `SESSIONS_REVOKED`: если позже вернуть адрес, старые входы останутся недействительными.
- **`signout ivan@company.com`** (или `@company.com`, или `--all`) — завершить входы на всех устройствах, не забирая
  доступ: на случай потерянного ноутбука. Человек может сделать это и сам кнопкой **«Выйти на всех устройствах»**,
  если у приложения есть том (`small volume add`).
- **`log`** — кто входил, когда, как (Google, Microsoft, ссылка на почту, личная ссылка) и с какого IP, а также
  отклонённые входы и запросы доступа, по всем деплоям: `magic_link` пишет их строками JSON в лог, а Railway хранит
  их столько, сколько хранит логи ваш тариф. `--json` — по объекту в строке.
- Первый `add` создаёт `SESSION_SECRET` — ключ подписи ссылок и сессий. Нужен настроенный способ входа: `small sso`
  или `small mail`.
- Адрес для ссылок в письмах `small` передаёт приложению сам, в `PUBLIC_URL` (только в Railway): после
  переименования домена в `<имя>.up.railway.app` Railway оставляет в `RAILWAY_PUBLIC_DOMAIN` прежний адрес, и
  ссылки вели бы на 404. Хотите ссылки на своём домене — укажите `PUBLIC_URL` в `small.json`, его `small` не трогает.
- Человек не из списка, введя свою почту, получает тот же ответ «Проверьте почту», а владельцу приходит запрос
  доступа (в лог и в Telegram, если подключён) с готовой командой `small access add его@адрес`.
- Работает во всех шаблонах: `python-http`, `fastapi`, `node-http` и `streamlit` (про `streamlit` — выше).

*По личной ссылке-приглашению*:
- **`add bob`** — создаётся токен, добавляется в `ACCESS_TOKEN` в формате `bob:токен`, приложение перезапускается,
  и ссылка печатается. Ссылка работает как пароль: войдёт любой, кому её переслали.
- **`revoke bob`** — после перезапуска не работают ни ссылка bob, ни его уже выданная кука; у остальных всё
  остаётся как было.

- **`list`** — у кого есть доступ: адреса и имена (токены скрыты).
- **Журнал входов** — `small access log` (выше). В сыром логе (`small logs`) каждый вход — одна строка JSON,
  например `{"message": "[magic-link] вход через Google: ivan@company.com, ip 203.0.113.7", "magic_link": "sign_in",
  "method": "google", ...}`; в обозревателе логов Railway их отбирает фильтр `@magic_link:sign_in`. Текст `message` —
  на языке владельца (`OWNER_LANG`, см. «Язык»).

**`small sso`** — вход рабочим аккаунтом. Кто может войти — по-прежнему список доступа.
- **`google`** — «Войти через Google» для аккаунтов Google Workspace и адресов Gmail. `small` печатает, что сделать в
  Google Cloud (около 5 минут: OAuth-клиент типа Web application), и точный redirect URI для регистрации, затем
  спрашивает ID клиента и секрет (секрет — из `GOOGLE_CLIENT_SECRET` или скрытым вводом).
- **`microsoft`** — «Войти через Microsoft» для сотрудников одной организации в Microsoft Entra. `small` печатает шаги
  (регистрация приложения, single tenant, секрет клиента) и redirect URI; `--tenant` принимает Directory (tenant) ID
  или ваш домен (`company.com`), который `small` сам превращает в ID.
- **Проверка до сохранения.** `small` предъявляет провайдеру ID клиента и секрет; неверную пару тот отклоняет, и
  ничего не сохраняется.
- **Какие аккаунты подходят.** Google: подтверждённые адреса Gmail или аккаунты организации Google Workspace; личный
  аккаунт Google, заведённый на рабочий адрес, отклоняется. Microsoft: только сотрудники вашей организации, без
  гостей и чужих организаций. Подробнее: [SECURITY.md](https://github.com/RuslanKazyradzi13/small-software/blob/main/SECURITY.md#threat-model).
- **Redirect URI**: `https://<приложение>/_access/sso/callback`, для `streamlit` — `https://<приложение>/`. Со своим
  доменом сначала укажите `PUBLIC_URL` в `small.json` и регистрируйте этот адрес.
- Если вход по почте не настроен, на странице входа только кнопки провайдеров; если настроено и то и другое — оба
  способа.
- **`off [google|microsoft]`** — выключить один или оба; без подкоманды — статус и redirect URI.

**`small mail`** — чем приложение отправляет письма для входа по почте.
- **`resend`** — через [Resend](https://resend.com) по HTTPS. Ключ `small` берёт из `RESEND_API_KEY` или
  спрашивает скрытым вводом. Railway на тарифе Hobby закрывает SMTP-порты, поэтому для Hobby это основной путь
  ([документация Railway](https://docs.railway.com/networking/outbound-networking)). Без подтверждённого в Resend
  домена письма уходят только на адрес вашего аккаунта Resend; для коллег подтвердите домен и укажите
  `--from "Отчёты <noreply@company.com>"`.
- **`smtp`** — свой почтовый сервер: `SMTP_URL` вида `smtp://логин:пароль@сервер:587` (или `smtps://…:465`).
  Адрес `small` берёт из переменной окружения `SMTP_URL` или спрашивает скрытым вводом. На Railway работает с
  тарифа Pro.
- Перед сохранением `resend` и `smtp` отправляют пробное письмо (`--to адрес`) тем же кодом, что и приложение.
  Не ушло — ничего не сохраняется, причина печатается. `--from` и `--to` работают с обеими подкомандами.
- **`log`** — вместо писем ссылка для входа пишется в лог приложения. Только для проверки: ссылка из лога
  пускает в приложение.
- **`off`** — выключить; без подкоманды — статус (`resend`, `smtp`, `log` или `off`).

**`small notify`** — запросы доступа приходят владельцу в Telegram.
- **`telegram`** — подключить бота. Создайте его у [@BotFather](https://t.me/BotFather) (`/newbot`). Токен бота
  `small` берёт из `TELEGRAM_BOT_TOKEN` или спрашивает скрытым вводом, чтобы он не остался в истории терминала.
  Затем `small` просит написать боту любое сообщение, сам находит ID чата, отправляет пробное уведомление и
  записывает `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в Railway и `small.json`. ID чата можно передать сразу:
  `--chat-id`.
- **Как выглядит уведомление.** Когда кто-то нажмёт «Запросить доступ» и оставит контакт, придёт сообщение: адрес
  приложения, контакт, IP и подсказка `small access add ИМЯ`. Работает во всех шаблонах (`python-http`, `fastapi`,
  `node-http`, `streamlit`) и в `magic-link` вообще. Запрос по-прежнему пишется и в лог.
- **`off`** — отключить; без подкоманды — статус.

**`small db`** — база данных в один шаг.
- **`add postgres`** — разворачивает Postgres из шаблона Railway (как `railway add --database postgres`) в проекте
  приложения и передаёт приложению `DATABASE_URL` в виде ссылки Railway `${{Postgres.DATABASE_URL}}`. Пароль
  хранится только в Railway, в `small.json` попадает лишь ссылка. Приложение ходит в базу по приватной сети Railway.
- **Запуск.** База стартует около минуты: если приложение подключается к ней при старте, первый запуск может её
  не застать.
- **`list`** — базы приложения и их статус.
- **`remove postgres`** — удалить базу вместе с данными (подтверждение именем или `--yes`), `DATABASE_URL` убирается.
- **`small destroy`** удаляет базы вместе с приложением.

**`small domain`** — свой домен вместо `*.up.railway.app`.
- **`add app.example.com`** — регистрирует домен в Railway и печатает DNS-записи для регистратора: CNAME на адрес
  Railway и, если Railway попросит, TXT-запись для подтверждения владения.
- **Сертификат.** Когда записи заработают (от минут до суток), Railway сам выпустит HTTPS-сертификат.
- **Ссылки-приглашения** работают и на своём домене: `https://app.example.com/?token=…`.
- **`list`** — домены и их состояние: «ждёт DNS-записей» / «DNS настроен», статус сертификата.
- **`remove`** — убрать домен.

**`small volume`** — постоянный диск приложения (том Railway).
- **`add`** — создаёт том в `/data` (`--mount` — другой путь, вне `/app`) и перезапускает приложение. Приложение может
  хранить там файлы, путь — в `RAILWAY_VOLUME_MOUNT_PATH`. Без подкоманды — путь и сколько занято.
- **Состояние входа.** `magic_link` хранит его на томе в `.magic-link.db` (SQLite): использованные ссылки для входа
  остаются использованными и после перезапуска, лимиты общие для всех процессов-воркеров, появляется кнопка
  «Выйти на всех устройствах». Без тома это состояние живёт в памяти, и перезапуск его забывает.
- **Цена.** С томом каждый деплой — несколько секунд простоя: две копии приложения не могут делить диск. У сервиса
  один том.

**`small sleep`** — режим сна Railway (serverless).
- **`on`** — без входящих запросов приложение засыпает и не тратит CPU и память; первый запрос будит его за
  несколько секунд. Удобно для приложений, которые открывают пару раз в день.
- **`off`** — приложение работает всегда; без аргумента — текущий режим.
- **Перезапуск.** Настройка вступает в силу после перезапуска, `small sleep` делает его сам (`--no-deploy` —
  отложить до следующего деплоя).

**`small env`** — переменные окружения приложения.
- **`list`** — переменные и где они заданы: `small.json + Railway`, `только Railway`, `Railway ≠ small.json`.
  Значения скрыты, `--values` их показывает. Служебные `RAILWAY_*` не выводятся.
- **`set` / `unset`** — меняют переменные сразу и в Railway, и в `small.json`; иначе следующий `small deploy`
  вернул бы старые значения. После изменения Railway перезапускает приложение один раз, `--no-deploy` это
  отключает. Если приложение ещё не задеплоено, меняется только `small.json`.
- **Удалённые переменные.** Переменную, убранную из `small.json` вручную, удаляйте командой `small env unset`.
  Тогда она исчезнет и из Railway.

**`small logs`** показывает лог последнего деплоя.
- **Какой лог.** По умолчанию лог приложения, с `--build` лог сборки. `-n` задаёт число строк (по умолчанию 100).
- **Режим слежения.** `-f` раз в 2 секунды дописывает новые строки, `Ctrl+C` выходит.
- **Формат.** Каждая строка выводится с локальным временем. Запросы с кнопки «Запросить доступ» видны как
  `[access-request] ...`, их удобно отфильтровать: `small logs | findstr access-request`.
- **Ограничение.** `-f` следит за деплоем, который был последним на момент запуска; после нового деплоя
  перезапустите команду.

**`small destroy`** удаляет приложение из Railway.
- **Что удаляется.** Если в проекте только сервисы этого приложения (сам сервис и базы из `small db`), удаляется
  весь проект: сервисы, домены, переменные, деплои, данные баз. Если `small deploy` в своё время привязал папку к
  проекту, где есть и чужие сервисы, удаляются только сервисы приложения, остальные остаются.
- **Подтверждение.** В терминале нужно ввести имя проекта. Без терминала (скрипт, CI) удаление происходит только
  с флагом `--yes`. При отказе ничего не удаляется.
- **Локальные файлы.** После удаления стирается `.small.json`, а `small.json` остаётся, так что следующий
  `small deploy` создаст новый проект с теми же настройками.

## Настройки: `small.json`

Необязательный файл в корне папки приложения:

```json
{
  "name": "my-custom-app-name",
  "env": {
    "OPENAI_API_KEY": "sk-...",
    "DEBUG": "true"
  }
}
```

| Поле | Что делает |
|---|---|
| `name` | Имя проекта и сервиса в Railway, а также желаемый поддомен `<name>.up.railway.app`. Приводится к `a-z0-9-`. Флаг `--name` главнее. |
| `env` | Переменные окружения сервиса. Имена: латиница, цифры и `_`, не с цифры. Значения: строки, числа или `true`/`false` (уходят в Railway строками: `"true"`, `"2"`). |

Оба поля необязательны, другие поля считаются ошибкой (так ловятся опечатки вроде `"envs"`). Ошибка в файле
останавливает деплой до любых обращений к Railway.

**Имя.** Пока папка не привязана к сервису (нет `.small.json`), явно заданное имя (из `small.json` или `--name`)
работает как идентификатор: если в Railway уже есть проект с таким именем, например после деплоя с другого
компьютера, `small` подключается к нему, а не создаёт дубликат. Если такого проекта нет, он создаётся. Если проектов с
таким именем несколько, деплой останавливается с ошибкой. `--new` всегда создаёт новый проект. Если папка уже
привязана, новое имя не применяется: `small` предупредит об этом. Чтобы привязать её к другому проекту, удалите `.small.json`.

**Переменные** записываются при каждом `small deploy`, до загрузки кода, так что новая сборка сразу их видит.
Используется `variableCollectionUpsert` (пакетная форма `variableUpsert`) с `replace: false`: переменные из `env`
добавляются или обновляются, а остальные переменные сервиса, например `ACCESS_TOKEN`, заданный в дашборде, не трогаются.
Переменная, удалённая из `env`, в Railway **остаётся**: удалите её командой `small env unset` или в дашборде
(сервис → Variables). Значения в вывод не печатаются, только имена.

Если в `env` их нет, `small deploy` сам передаёт приложению `PUBLIC_URL` (при входе по почте, см. `small access`) и
`OWNER_LANG` (язык small, см. «Язык»). При пустом `env` `small deploy` не записывает никаких переменных, в том числе
`OWNER_LANG`.

**Секреты.** `small.json` в корне не загружается в Railway вместе с кодом. Если в нём лежат ключи, добавьте его
в `.gitignore`, чтобы он не попал в git.

`small.json` и `.small.json` — разные файлы. Первый вы пишете сами (настройки). Второй `small` создаёт сам: в нём ID
проекта, сервиса и домен.

## Что происходит внутри

1. Читается и проверяется `small.json`, если он есть.
2. Код папки упаковывается в `.tar.gz`. Учитываются `.gitignore` и `.railwayignore` в корне, всегда исключаются
   `.git`, `node_modules`, `__pycache__`, `.venv`, `venv`, а также `small.json` и `.small.json` в корне.
3. GraphQL `https://backboard.railway.com/graphql/v2`: `me.workspaces` (выбор workspace). Если имя задано явно,
   `projects` ищет одноимённый проект. Затем `projectCreate` и `serviceCreate`, если подходящего проекта нет.
4. `serviceDomainCreate` создаёт домен `*.up.railway.app`. Если `<name>.up.railway.app` свободен
   (`serviceDomainAvailable`), домен переименовывается в него (`serviceDomainUpdate`). Если имя занято, остаётся домен,
   который выдал Railway. Если сервис найден по имени и домен у него уже есть, используется существующий. Домен
   создаётся до загрузки кода: его адрес нужен уже первой сборке (ссылки в письмах для входа).
5. `variableCollectionUpsert` записывает переменные из `small.json`, а также `PUBLIC_URL` и `OWNER_LANG` (см. выше).
   При пустом `env` этот шаг пропускается.
6. Архив уходит в `POST https://backboard.railway.com/project/{projectId}/environment/{environmentId}/up?serviceId=...`.
   Это тот же эндпоинт, что у официального `railway up`. Он запускает сборку и возвращает `deploymentId`.
7. Каждые 3 с опрашивается `deployment(id) { status }` до `SUCCESS` (или `SLEEPING`) либо до статуса ошибки:
   `FAILED`, `CRASHED`, `REMOVED`, `REMOVING`, `SKIPPED`, `NEEDS_APPROVAL`. При `FAILED` выводится `buildLogs`, при
   остальных ошибках — `deploymentLogs`.
8. Печатается `https://<домен>`.

ID проекта, сервиса и домен сохраняются в `.small.json` в папке приложения. Повторный `small deploy` выкатывает
новую версию в тот же сервис и не создаёт новый проект. Файл записывается сразу после создания или привязки проекта,
поэтому упавшая сборка не плодит проекты при повторе.

Сборку выполняет Railpack: он сам определяет язык. Для Python достаточно `app.py` или `main.py`
(+ `requirements.txt` для зависимостей), стартовая команда будет `python app.py`. Приложение должно слушать
`0.0.0.0:$PORT`.

## Тесты

```bash
python -m unittest discover -s tests
```

Тесты поднимают локальный мок Railway API (GraphQL + эндпоинт загрузки) и прогоняют полный сценарий: первый деплой,
повторный, упавшая сборка, краш, занятый домен, несколько workspace, неверный токен, правила игнорирования.

Тесты шаблонов на настоящих фреймворках пропускаются, если фреймворк не установлен; остальные проходят.
- тесты `streamlit`: гейт доступа через `streamlit.testing.v1.AppTest` (личные токены; вход по почте: форма,
  одноразовая ссылка, кука сессии, отзыв, выход; вход через Google на локальном провайдере, отказы, выход на всех
  устройствах) и сервер через `python app.py`.
- 2 теста `fastapi`: `TestClient` и `uvicorn main:app`, как его запускает Railway, плюс проверка, что токен скрыт
  в access-логе.

`small env` и `small access` проверяются на моке Railway:
- источники переменных и скрытые значения;
- `set` / `unset` вместе с `small.json`, один перезапуск, `--no-deploy`;
- до первого деплоя;
- сбой Railway, при котором `small.json` не меняется;
- выдача, отзыв и `link --as`, отзыв последнего токена, токен только в Railway.

Кнопки дашборда: редирект «Открыть по ссылке» и защита от чужих путей, «Логи» без токена, с Railway и при его
недоступности. Режим сна и оценка расхода в дашборде, ошибки Railway при расчёте расхода.

`small sso`, `volume`, `access log` и `access signout` проверяются на моках Railway, Google и Microsoft: проверка
данных клиента, неверный секрет, при котором ничего не сохраняется, домен вместо tenant ID, redirect URI для Streamlit
и своего домена, старый код `magic_link`, том и путь монтирования, таблица журнала, `--json` и инструмент MCP, выход по
адресу, домену и `--all`, забывание старых выходов.

`small sleep`, `db`, `domain`, `notify` проверяются на моках Railway и Telegram Bot API:
- включение и выключение сна, повторное включение без запросов, `--no-deploy`;
- развёртывание шаблона Postgres со значениями по умолчанию, ссылка `DATABASE_URL`, ошибка workflow, удаление
  базы, `destroy` вместе с базой;
- DNS-записи своего домена, нормализация адреса, повтор и удаление;
- поиск чата бота, пробное сообщение, неверный токен, «боту никто не написал», отсутствие токена.

`small init` проверяется так (шаблон `streamlit` тоже):
- шаблоны `python-http` и `node-http`, уникальность имени и токена (у `fastapi` и `streamlit` свои тесты, см. выше);
- защита существующих файлов: отказ, `--force`, вопрос в терминале;
- дополнение `.gitignore` без дублей;
- связка `init` → `deploy`;
- `python-http` и `node-http` запускаются как настоящие серверы (403 → ссылка → кука → 200);
- копии `magic_link.py` и `magic-link.js` в шаблонах совпадают с исходниками в папке `magic-link/` репозитория.

`small dashboard` проверяется так (живые статусы — на моке Railway: успех, частичный сбой, нет сети, таймаут,
неверный токен, мусорный статус, отсутствие токена в ответе):
- сканирование: вложенные папки, служебные папки, папки внутри приложения, лимит глубины, приложение в корне;
- описание приложений и отсутствие значений переменных в выдаче;
- битые файлы и небезопасные ссылки;
- страница и API, в том числе повторное сканирование;
- 403 на чужой `Host`;
- запасной порт;
- сама команда: URL, браузер, `--no-browser`.

`small.json` проверяется отдельно:
- имя и переменные, порядок «переменные до загрузки»;
- исключение файла из архива;
- привязка к существующему проекту и неоднозначное имя;
- `--new` и приоритет `--name`;
- уже привязанная папка и некорректный файл.
`SMALL_API_URL` переопределяет адрес API.

## Ограничения

- Читаются только корневые `.gitignore`/`.railwayignore`, вложенные не учитываются.
- Создаётся один сервис в окружении `production`. Базы данных — только Postgres (`small db`).
